# 需求量看板 · 公共共享版

无需注册或登录；**所有访问者共用、查看和编辑同一份数据**。
任何拿到网站地址的人都能改变数据，不适合保密或强权限管理场景。

## 文件

- `demand-dashboard.html`：本地源页面，保留北京/成都小组、月份、工作日、产品调量逻辑。
- `shared-cloud.js`：公共 Supabase 读取、保存、同步及断网冲突保护。
- `supabase-shared.sql`：独立共享表、历史备份、RLS 和受限写入函数。
- `docs/`：GitHub Pages 发布文件，仅含页面、脚本；不包含 Excel 或真实数据备份。

前端仅使用项目公开 Publishable Key。没有 Service Role Key、数据库密码、管理员口令。
仓库中的初始数据是空白模板，真实数据应从本地迁入 Supabase，不能提交进 Git。

## 第一步：建立数据库（只做一次，无需编写代码）

1. 登录 Supabase，打开项目 `mjqjcwwthhjofmxyrulp`。
2. 左侧点击 **SQL Editor**，再点击 **New query**。
3. 打开本仓库的 `supabase-shared.sql`，复制全部内容，粘贴到 SQL Editor。
4. 点击 **Run**。执行成功后会建立 `demand_shared_state`、`demand_shared_history` 和保存函数。
5. 不需要填写邮箱、创建用户或开启匿名注册。不要执行旧的 `supabase-setup.sql`：那是之前的单人版。

新脚本不会修改旧单人表，也不会删除现有正式记录；重复执行不会清空共享数据。
SQL Editor 可能提示政策/函数配置变更，请核对执行的确实是此文件。

## 第二步：导入你的真实数据（只做一次）

1. **在原电脑、原浏览器里**打开原来的本地 `demand-dashboard.html`。
2. 核对预览月份、数字是否是你要公开共享的数据。不要把空白模板当作真实数据上传。
3. 点击“备份并公开当前数据”，确认后会先下载 JSON 备份，再写入 Supabase，并重新读取校验。
4. 看到“已保存到云端”后，再打开 GitHub Pages 地址，核对数据。
5. 如果本地页面没有原数据，先找到此前下载的 JSON 备份；点击“导入JSON备份预览”再迁移。
6. **本地 file 页面和 GitHub Pages 是不同来源，不能相互读取 localStorage。** 因此必须在原页面完成迁移，或用 JSON 文件传递。

云端已有数据时不会再显示首次导入按钮，避免覆盖。原本地文件版本还保留在本机 `.local-backups/`（不会上传）。

## 数据保护范围

- `demand_shared_state` 只有一份公共文档；无“属于某个访客的私有数据”。
- `device_id` 仅作本机标识，**不作为权限凭证**。共享模式不使用设备隔离。
- 匿名用户只能读取当前共享文档的公开列，不能直接 INSERT/UPDATE/DELETE 表或读取历史表。
- 所有写入必须调用 `save_demand_shared`，在数据库端检查结构、数值范围、最大1MB、最多120个月、版本号。
- 每秒最多接受一次公共写入，每天最多2000次。客户端合并短时间内修改。
- 每次成功保存将快照写入历史表；删除月份也是新版本，不会物理删除历史。
- 历史表仅项目管理员可访问。SQL未给公开访问者开放其他私人业务表权限。
- 这些限制**不能识别合法同事与陌生人，也不能完全阻止滥用**；恶意访问者仍能修改允许公开编辑的数据、耗尽写入额度。若不能接受，需要增加受验证身份或服务端编辑口令，不能只用前端按钮限制。
- 仍需定期下载独立 JSON 备份；同项目历史无法防止整个 Supabase 项目被删除。

## 同步与断网

- 页面打开、重新聚焦、切回标签页、恢复联网及前台每5秒检查一次云端。
- 远程更新到达时自动刷新；输入聚焦期间暂缓重绘，避免打断输入。
- 月份选择是每个浏览器的视图偏好，不会迫使其他人的界面一起跳月份。
- 断网时保留本地缓存和未同步草稿，恢复联网后再保存。
- 数据库用原子版本校验避免旧数据覆盖新数据；冲突时暂停编辑，保留草稿，要求下载备份再读取云端。
- 无法安全自动合并同一产品的两次修改；冲突后需对照备份重做修改。
- “删除本月”会影响所有人，需确认并下载备份。2026年8月基础月份不可删除。

## 管理员暂停公共编辑

在 SQL Editor 执行以下语句（仅在需要时执行，常规部署不需要）：

```sql
update public.demand_shared_state set accept_writes=false where id=1;
```

恢复编辑时设为 `true`。恢复旧版本前先备份当前数据，在历史表选定目标版本，再由管理员进行恢复；不要删除历史。
